# VPN Авто

Небольшое Android-приложение, которое автоматически выбирает VPN по типу сети и доверенным
Wi-Fi:

- **доверенная Wi-Fi** (текущая точка совпала с сохранённой парой SSID+BSSID) →
  **VPN выключен**;
- **незнакомая Wi-Fi** (SSID нет в списке, SSID недоступен, BSSID не совпал с сохранённой
  точкой или сеть открыта) → **Tailscale** (`com.tailscale.ipn`) с exit node;
- **мобильная сеть** → **WDTT Plus** (`com.wdtt.plus`);
- **сети нет или Ethernet** → VPN не переключается, в статусе «ожидание».

Открытые сети и сети, у которых не удалось получить BSSID, доверенными не считаются: без
привязки к точке нельзя отличить домашнюю сеть от подделки с тем же SSID.

При смене сети приложение приводит VPN к состоянию, которое требует правило.

Автопереключение можно выключить. В приложении также есть ручные кнопки включения/выключения
обоих VPN и открытия их экранов.

Отдельно приложение управляет **exit node Tailscale**: включает его на незнакомой Wi-Fi и
снимает на доверенной Wi-Fi или при потере интернета, не отключая сам Tailscale. Правило
exit node работает независимо от автопереключения, пока включено «Управлять exit node».

## Как это работает

Android не позволяет одному приложению напрямую запустить `VpnService` другого приложения:
разрешение `BIND_VPN_SERVICE` есть только у системного VPN-фреймворка, а `VpnService.prepare()`
чужого пакета нельзя корректно вызвать извне. Поэтому используются штатные экспортированные
точки управления, которые предоставляют сами клиенты:

| Клиент | Получатель | Действие |
|---|---|---|
| Tailscale | `com.tailscale.ipn.IPNReceiver` | `com.tailscale.ipn.CONNECT_VPN` / `com.tailscale.ipn.DISCONNECT_VPN` |
| WDTT Plus | `com.wdtt.plus.VpnWidgetProvider` | `com.wdtt.plus.ACTION_WIDGET_TOGGLE` |

Broadcast отправляется явно на пакет:

```java
new Intent("com.tailscale.ipn.CONNECT_VPN").setPackage("com.tailscale.ipn");
new Intent("com.wdtt.plus.ACTION_WIDGET_TOGGLE").setPackage("com.wdtt.plus");
```

Команда WDTT — это **toggle**: если WDTT запущен, она останавливает его, иначе запускает.
Поэтому приложение сначала определяет состояние VPN и не отправляет toggle, если WDTT уже
активен или, по его данным, вот-вот восстановится после паузы на доверенной Wi-Fi.

## Определение состояния

`ConnectivityManager.getAllNetworks()` перебирает все сети. Сети с `TRANSPORT_VPN` игнорируются
при определении типа доступа. Wi-Fi имеет приоритет: подключённый Wi-Fi считается Wi-Fi даже без
интернета.

Активный VPN определяется по первому успешному способу:

1. `NetworkCapabilities.getOwnerUid()` — только на Android 11 (API 30) и новее; на более
   старых версиях и на части прошивок владелец недоступен. Если владелец известен и это
   не Tailscale и не WDTT Plus, VPN сразу получает тип `OTHER`: адресные и маршрутные
   эвристики ниже не применяются, иначе чужой клиент с похожими адресами был бы принят
   за свой.
2. Основной способ при неизвестном владельце — адреса интерфейса
   `LinkProperties.getLinkAddresses()`:
   - WDTT Plus: `10.66.66.0/24`;
   - Tailscale: `100.64.0.0/10` (IPv4) или `fd7a:115c:a1e0::/48` (IPv6).
   Префикс самого `LinkAddress` не важен: сравниваются только биты адреса.
3. Fallback по маршрутам `LinkProperties.getRoutes()`: те же подсети; маршрут должен
   целиком лежать внутри целевого префикса.

Сравниваются байты адресов, а не строки. Если VPN активен, но не опознан,
ему присваивается тип `OTHER`, и автоматическое переключение не выполняется — приложение
попросит отключить неизвестный VPN вручную.

Маршрут по умолчанию (`0.0.0.0/0` или `::/0`) как признак exit node проверяется только
в найденной VPN-сети Tailscale, а не в любой VPN: у другого клиента он может быть всегда.

## Доверенные Wi-Fi

Собственный список доверенных сетей приложения хранится в `SharedPreferences` под ключом
`trusted_ssids` и не покидает устройство. Доверие привязано к точке доступа: одна запись —
это пара **SSID + BSSID**. В `trusted_ssids` пара хранится как `SSID<TAB>BSSID`, в
интерфейсе показывается как `SSID | BSSID`.

На доверенной паре приложение считает VPN ненужным и выключает Tailscale или WDTT Plus.

В карточке **«Доверенные Wi-Fi»** показаны текущий SSID и его статус, поле списка и счётчик
сохранённых записей.

- **Добавить текущую** — сохраняет пару SSID+BSSID текущей точки (и добавляет её в поле
  ввода); если эта пара уже есть, приходит сообщение об этом. Несколько точек одного SSID
  поддерживаются как отдельные записи — так работают mesh и роуминг. Старая запись того же
  SSID без BSSID при этом заменяется привязанной.
- **Сохранить** — разбирает поле и сохраняет список.
- Записи можно вводить по одной: переводом строки, запятой или точкой с запятой.

Нормализация выполняется и при вводе, и при сохранении, и при сравнении:

- SSID: пробелы по краям обрезаются, одна пара обрамляющих двойных кавычек снимается
  (система отдаёт SSID в кавычках);
- BSSID: приводится к нижнему регистру `xx:xx:xx:xx:xx:xx`; служебные значения
  `00:00:00:00:00:00` и `02:00:00:00:00:00`, которыми Android подменяет недоступный
  BSSID, считаются отсутствием BSSID;
- пустые значения отбрасываются, дубликаты схлопываются;
- SSID сравнивается точно, после нормализации, с учётом регистра.

Статусы в карточке:

| Статус | Когда |
|---|---|
| «Доверенная» | SSID и BSSID совпали с сохранённой парой |
| «SSID без привязки к точке…» | есть старая запись только по SSID; она не доверяется, пока не добавлена текущая точка |
| «Другая точка с этим SSID…» | SSID совпал, BSSID другой — VPN не отключается |
| «BSSID недоступен…» | BSSID текущей точки получить не удалось |
| «Открытая сеть…» | сеть без шифрования — не доверяется |
| «Не доверена» | пары нет в списке |
| «Нет доступа» | нет разрешения на местоположение |
| «Геолокация выключена» | разрешение есть, но геолокация в системе выключена |
| «SSID недоступен» | SSID скрыт системой или пришёл как `0x…` |
| «Wi-Fi не подключён» | текущая сеть не Wi-Fi |

Доверие работает fail-closed: пустой SSID, недоступный BSSID и известная открытая сеть
не подтверждают доверие, и применяется правило для незнакомой Wi-Fi. Если SSID совпал,
но ни одна сохранённая точка не подошла (BSSID другой или недоступен), доверие не
подтверждается: для старой записи без BSSID это UNBOUND, иначе MISMATCH. VPN не отключается.
Старые записи только по SSID (до перехода на пары) получают статус UNBOUND и не доверяются,
пока пользователь не нажмёт «Добавить текущую» на этой точке.

Если Wi-Fi подключена, но SSID недоступен — нет разрешения, выключена геолокация, сеть
скрыта (`<unknown ssid>`) или система вернула `0x…`, — приложение не может подтвердить
доверие и применяет правило для **незнакомой Wi-Fi**: Tailscale + exit node. VPN при этом
не выключается. Если Wi-Fi не подключена или сети нет (в том числе Ethernet), VPN не
переключается: в статусе «Нет сети — ожидание».

После изменения списка («Добавить текущую» или «Сохранить») приложение через 600 мс
принудительно применяет правило — без ожидания следующего события сети.

### Разрешения для SSID

На всех версиях Android, включая 13+, имя Wi-Fi (`WifiInfo.getSSID()`) — location-sensitive
поле, поэтому приложению нужен `ACCESS_FINE_LOCATION`:

- `ACCESS_FINE_LOCATION` запрашивается на всех версиях Android;
- `ACCESS_COARSE_LOCATION` запрашивается вместе с ним: на Android 12+ запрос FINE без COARSE
  игнорируется, на более старых версиях COARSE безвреден;
- геолокация должна быть включена в системных настройках: при выключенной геолокации Android
  накладывает на SSID маску (`<unknown ssid>`), даже если разрешение выдано;
- `ACCESS_BACKGROUND_LOCATION` («Разрешить всегда») нужен, чтобы SSID читался, когда экран
  приложения закрыт. С разрешением «при использовании» система применяет к SSID ограничение
  while-in-use и возвращает маску: `WifiServiceImpl.getConnectionInfo()` снимает
  `REDACT_FOR_ACCESS_FINE_LOCATION` только при успешной проверке `OPSTR_FINE_LOCATION`, а
  foreground-сервис типа `specialUse` не получает `PROCESS_CAPABILITY_FOREGROUND_LOCATION`
  (её выдаёт только FGS с типом `location`).

Сервис остаётся `specialUse`: тип `location` нельзя запускать из `BOOT_COMPLETED` без
фонового доступа, а с фоновым доступом он не нужен.

`NEARBY_WIFI_DEVICES` (даже с `neverForLocation`) SSID не открывает и приложению не нужен:
оно не сканирует сети и не ищет nearby-устройства, а только читает текущее подключение через
`WifiManager.getConnectionInfo()`.

Если доступа нет, в диагностике отображается «Нет доступа», а в карточке доступна кнопка
**«Разрешить доступ к местоположению»**. Если разрешение выдано, но геолокация выключена,
кнопка меняется на **«Открыть настройки геолокации»**, а статус — на «Геолокация выключена».
Если выдано только «При использовании», кнопка называется **«Разрешить доступ всегда»** и
открывает настройки приложения (Android 11+; путь: Разрешения → Местоположение → «Разрешить
всегда»), а в диагностике отображается «Только при использовании».
Без разрешения или при выключенной геолокации SSID неизвестен всегда, и работает fallback
на Tailscale. С доступом «при использовании» SSID читается, пока открыт экран приложения;
фону нужен доступ «всегда», иначе Android маскирует имя сети.

## Ограничение Android 12+ и доверенные сети WDTT

Начиная с Android 12 фоновый запуск foreground-сервиса (а WDTT запускает VPN-сервис) может быть
заблокирован системой с `ForegroundServiceStartNotAllowedException`. Приложение не может выдать
за WDTT разрешение на такой запуск.

Решение — «Доверенные сети» в самом WDTT Plus. Это отдельный от `trusted_ssids` механизм:
список в «VPN Авто» задаёт правила переключения, а список WDTT нужен, чтобы WDTT сам не
запускался на домашней Wi-Fi.

- добавьте домашнюю Wi-Fi в список доверенных сетей WDTT;
- тогда WDTT сам ставит себя на паузу при подключении к ней и сам восстанавливается при выходе
  в мобильную сеть;
- приложение запоминает, что WDTT реально ушёл в паузу на доверенной Wi-Fi, и в мобильной сети
  после выхода с Wi-Fi ждёт до 12 секунд авто-восстановления;
- если WDTT был на паузе и не восстановился, в автоматическом режиме toggle не отправляется:
  приходит уведомление с кнопкой открытия WDTT Plus;
- если WDTT не был в паузе (холодный старт, например после перезагрузки или ручной остановки),
  приложение после 12 секунд ожидания отправляет toggle и запускает WDTT;
- ручной запуск «Применить сейчас» ждёт те же 12 секунд: иначе toggle мог бы прийти в паузу.
  После ожидания toggle отправляется, даже если WDTT был в паузе и не восстановился.
  Ожидание действует в пределах двух минут после ухода с Wi-Fi.

Признак паузы хранится в настройках приложения (`wdtt_paused_on_wifi`). Он сбрасывается, когда
WDTT активен или остановлен самим приложением, а также после успешного восстановления. После
успешного переключения уведомление об ошибке снимается автоматически.

В UI есть чекбокс **«Учитывать авто-паузу WDTT Plus на его доверенных сетях»** (по умолчанию
включён). Если доверенные сети в WDTT не настроены, снимите галочку: приложение будет сразу
отправлять toggle, но на Android 12+ запуск может не сработать. Этот флажок относится к
собственному списку WDTT и не связан со списком «Доверенные Wi-Fi» приложения.

Сервис подписан на два callback'а: `registerDefaultNetworkCallback()` и отдельный
`registerNetworkCallback()` на `TRANSPORT_WIFI`. Default-сеть может остаться мобильной, и
тогда подключение Wi-Fi не вызовет default callback; второй callback закрывает этот случай.
Дополнительно раз в 30 секунд сервис сверяет фактический тип сети и выполнение правила —
на случай, если событие сети потерялось. При уходе с Wi-Fi Tailscale отключается сразу,
не дожидаясь общей задержки перед применением правила.

Для Android 14+ в манифесте явно указан
`android:foregroundServiceType="specialUse"` (и разрешение `FOREGROUND_SERVICE_SPECIAL_USE`),
поэтому foreground-мониторинг не падает при запуске.

## Настройка

1. **Tailscale**: установите, войдите в аккаунт и разрешите VPN-подключение.
2. **WDTT Plus**: установите, импортируйте профиль, разрешите VPN и добавьте домашнюю Wi-Fi в
   «Доверенные сети» WDTT.
3. Разрешите приложению доступ к местоположению и выберите «Разрешить всегда»: без этого
   Android скрывает имя Wi-Fi, когда приложение работает в фоне.
4. Добавьте домашнюю сеть в «Доверенные Wi-Fi» приложения (кнопка «Добавить текущую»).
5. Если нужен exit node: в карточке **«Exit node»** укажите имя ноды и tailnet-IP, затем
   включите «Управлять exit node».
6. Разрешите приложению уведомления (Android 13+) и отключите для него оптимизацию батареи.
7. Включите «Автопереключение». Приложение запустит foreground-сервис мониторинга и сразу
   применит текущее правило.
8. На устройствах с агрессивным энергосбережением (Xiaomi, Huawei, Samsung и др.) разрешите
   автозапуск приложения в настройках прошивки.

## Ручные кнопки

- **Tailscale вкл / выкл** — отправляет CONNECT/DISCONNECT, только если это действительно нужно.
- **WDTT вкл / выкл** — отправляет toggle, только если состояние WDTT позволяет понять, что
  произойдёт.
- **Открыть Tailscale / Открыть WDTT Plus** — запускает экран соответствующего приложения.
- **Применить сейчас** — принудительно применяет правило, даже если автопереключение выключено.

Кнопки учитывают текущее состояние: «вкл» недоступна, если любой VPN уже активен, «выкл» —
если активен не тот VPN.

## Exit node

Приложение управляет выбором exit node в Tailscale, не отключая сам Tailscale: включает
exit node на незнакомой Wi-Fi, снимает на доверенной Wi-Fi и при потере интернета.

### Команда Tailscale

Используется штатный broadcast, как и для остальных команд:

```java
Intent intent = new Intent("com.tailscale.ipn.USE_EXIT_NODE");
intent.setPackage("com.tailscale.ipn");
intent.putExtra("exitNode", "routeweave-exit");   // "" — снять exit node
intent.putExtra("allowLanAccess", false);
sendBroadcast(intent);
```

`exitNode` — имя ноды из списка Exit Nodes (короткое имя или FQDN). При снятии
передаётся пустая строка. Tailscale остаётся подключённым: меняется только маршрут по
умолчанию, доступ к домашней сети сохраняется (в том числе с `allowLanAccess`).

Признак применённого exit node — маршрут по умолчанию (`0.0.0.0/0` или `::/0`) в
`LinkProperties` найденной VPN-сети Tailscale. Без exit node там есть только `100.64.0.0/10`.

### Подтверждение включения

После команды включения приложение ждёт до 12 секунд и проверяет, появился ли маршрут по
умолчанию в сети Tailscale. Признак `applied` ставится только после этого подтверждения, и
только тогда exit node берётся под watchdog. Если маршрут не появился, приходит ошибка, а
повтор назначается по backoff.

### Правило для незнакомой Wi-Fi

При применении правила на незнакомой Wi-Fi приложение отдельно проверяет exit node:
если он не активен, отправляется команда включения; если уже активен, ничего не меняется.
Если Tailscale ещё не подключён, команда откладывается до подключения — такое ожидание
видно в карточке «Exit node».

Если имя ноды изменить при активном exit node, команда отправляется заново с новым именем.
Если очистить имя, exit node, включённый приложением, снимается. Правило работает
независимо от автопереключения, пока включено «Управлять exit node».

Кнопка **«Включить сейчас»** доступна, только когда установлен Tailscale, включено
«Управлять exit node» и задано имя ноды; **«Снять сейчас»** (выключить exit node) — когда
установлен Tailscale.

### Watchdog

Раз в 30 секунд, только когда exit node включён приложением и подтверждён, есть сеть и не
идёт подтверждение или повтор, приложение проверяет интернет **через активную сеть**, то
есть через сам exit node:
TCP-подключение по очереди к `77.88.8.8:53`, `87.250.250.242:443`, `8.8.8.8:53`,
`1.1.1.1:443` (таймаут 2 с на попытку). Адреса выбраны так, чтобы работать и из РФ,
и через зарубежный VPS: Яндекс DNS/ya.ru плюс Google DNS и Cloudflare как резерв.

Проверка пропускается, если экран выключен или устройство в Doze, а также если ни одна
физическая сеть не помечена системой как validated: в этих условиях пробы дают ложные сбои,
и счётчик неудач не растёт.

- две неудачи подряд (примерно 60 секунд) → exit node снимается, приходит уведомление
  «Exit node снят: нет интернета», запускается автовосстановление с backoff;
- задержка перед попытками — 5, 10, 20 и 30 минут; после пяти неудачных попыток
  автовосстановление останавливается и приходит ошибка «не удалось восстановить exit node,
  проверьте вручную»;
- перед возвратом проверяются `tailnet-IP:41641`, `:22`, `:443` и `:80` (таймаут 3 с):
  если сервер отвечает, exit node включается обратно, если нет — следующая попытка по
  backoff;
- если tailnet-IP не задан, автовосстановление останавливается: приходит ошибка
  «не задан IP сервера — автовосстановление остановлено, проверьте вручную»;
- счётчик неудач сбрасывается при успешной проверке;
- после включения exit node действует пауза 90 секунд: Tailscale нужно время на
  перестройку маршрута, иначе watchdog снял бы только что включённую ноду; такая же
  пауза есть после старта процесса (перезагрузка, запуск сервиса).

### Настройки (по умолчанию)

| Настройка | Ключ | По умолчанию |
|---|---|---|
| Управлять exit node | `exit_manage_enabled` | выключено |
| Имя ноды | `exit_node_name` | не задано |
| Tailnet-IP для проверки | `exit_node_ip` | не задан |
| Разрешить локальную сеть | `exit_node_allow_lan` | выключено |
| Watchdog | `exit_watchdog_enabled` | включено |

Имя и IP меняются в карточке **«Exit node»**; имя должно совпадать с названием
устройства в списке Exit Nodes в Tailscale. По умолчанию оба поля пусты и управление
выключено: заполните их и включите его, иначе exit node не применяется. Без IP watchdog
не может проверить сервер и автоматически вернуть exit node после снятия.

### Ограничение

Команда `USE_EXIT_NODE` применяется, только когда Tailscale подключён. Если в момент
команды VPN выключен, приложение запоминает необходимость и применяет команду позже,
при подключении Tailscale.

Подтверждение идёт по появлению маршрута по умолчанию и не различает конкретную ноду:
если Tailscale уже использует другой exit node, маршрут есть, и команда считается
применённой. Проверить, какая именно нода выбрана, средствами framework нельзя.

## Что нового в 1.3

- доверие Wi-Fi привязано к паре SSID+BSSID и работает fail-closed: старые записи без
  BSSID не доверяются, открытые сети и недоступный BSSID доверие не подтверждают;
- состояние exit node: подтверждение появлением default route, backoff и watchdog с
  пропусками при выключенном экране, Doze и невалидной сети;
- сервис слушает два сетевых callback'а (default и отдельный Wi-Fi) и раз в 30 секунд
  сверяет тип сети и выполнение правила;
- канал важных уведомлений `vpn_alerts_v2` и in-app баннер, если уведомления выключены;
- снимок состояния для интерфейса раз в 5 секунд и кэш текста уведомления на 25 секунд;
- поведение IME и прокрутки: поле списка не перехватывает прокрутку, позиция экрана
  сохраняется при повороте;
- единый источник версии `version.properties`; атомарная публикация APK и защита keystore;
- unit-тесты чистой логики и Android CI; старый сборочный путь удалён; backup выключен,
  BootReceiver не экспортирован.

## Сборка

Единственный поддерживаемый путь сборки — `build.sh`. Android Studio и другие системы
сборки не поддерживаются: кроме `build.sh` файлов сборки в проекте нет.

Требования:

- JDK 17 (`JAVA_HOME` или `$HOME/.local/opt/jdk-17`, иначе `javac` из `PATH`);
- Android SDK (`SDK`, `ANDROID_HOME`, `ANDROID_SDK_ROOT` или `$HOME/Android/Sdk`);
- build-tools `35.0.0`, platform `android-35`, `python3`.

Версия приложения и код версии задаются только в `android/version.properties`
(`VERSION_NAME` и `VERSION_CODE`). `build.sh` подставляет их в `BuildConfig`, манифест и
имя APK; в остальном тексте README номер версии не хардкодится.

Первая сборка создаёт локальный keystore (явное разрешение обязательно):

```bash
INIT_KEYSTORE=1 KEYSTORE_PASS='пароль' ./build.sh
```

Обычная сборка:

```bash
KEYSTORE_PASS='пароль' ./build.sh
```

Скрипт генерирует манифест с `package`, собирает ресурсы через `aapt2`, компилирует
Java 8 через `javac`, конвертирует классы в dex через `d8`, добавляет `classes.dex` в APK,
выравнивает `zipalign`, подписывает `apksigner` и публикует результат.

Результат: `dist/VpnSwitcher-<VERSION_NAME>.apk` — имя версии берётся из
`android/version.properties`. APK собирается и подписывается в `build/out/`, а в `dist/`
попадает атомарным `mv` только после `apksigner verify`; при любой ошибке прошлый APK в
`dist/` не изменяется. APK других версий скрипт не удаляет, а только перечисляет с
предупреждением.

APK подписан **локальным отладочным ключом** `keystore/vpnswitch.keystore` (alias
`vpnswitch`); путь можно переопределить переменной `KEYSTORE_PATH`. Ключ не попадает в
репозиторий (каталог `keystore/` в `.gitignore`). Скрипт требует существующий keystore:
новый создаётся только при `INIT_KEYSTORE=1`. Пароль задаётся `KEYSTORE_PASS`, передаётся
инструментам через временный файл (не через argv) и не должен попадать в историю команд.
Файл keystore получает права `600`. Каталог получает `700`, только если он находится
внутри репозитория; для внешнего `KEYSTORE_PATH` каталог нужно защитить самостоятельно.
Сохраните keystore и пароль: без них обновление не установится поверх. После подписи
скрипт печатает SHA-256 сертификата. Ключ не подходит для публикации в магазинах.

Контракт проекта — Java 8 (`-source 8 -target 8` в `build.sh`).

Проверки перед релизом:

- `./tests/run-unit-tests.sh` — unit-тесты чистой логики (`Logic.java`): обычный `javac`,
  без Android SDK и эмулятора, 195 проверок;
- `./tests/release-safety.sh` — релизная безопасность: успешная сборка, затем сборка с
  неверным и с отсутствующим паролем; прошлый APK в `dist/` не должен измениться.

CI: `.github/workflows/android.yml` запускается на push и pull request в `main` при
изменениях в `android/**` (и в самом workflow) и выполняет shellcheck для `build.sh` и
`tests/*.sh`, unit-тесты, сборку с временным keystore, `apksigner verify`, `zipalign -c 4`,
`aapt2 dump badging`, сверку `versionName`/`versionCode` с `version.properties` и
публикует APK как artifact.

## Диагностика

Логи приложения:

```bash
adb logcat -s VpnSwitcher
```

Полезные сообщения:

- `currentKind` — определённый тип сети;
- `currentSsid` — причина, по которой SSID недоступен (сам SSID в лог не пишется);
- `detectVpn` — найденный VPN, способ определения (owner/address/route) и владелец;
- `broadcast` — отправленная команда;
- `apply` — причина запуска и ход переключения;
- `exitnode` — watchdog, проверки сервера и отправка `USE_EXIT_NODE`;
- `FAIL` — причина ошибки (дублируется уведомлением).

В самом приложении карточка «Диагностика» показывает, установлены ли клиенты, разрешены ли
уведомления, отключена ли оптимизация батареи и есть ли доступ к SSID. Строка доступа к SSID
показывает «Разрешён», «Только при использовании», «Геолокация выключена» или «Нет доступа».

## Известные ограничения

- Нельзя запустить или остановить `VpnService` чужого приложения напрямую — только через
  экспортированные broadcast-точки, если клиент их предоставляет.
- WDTT управляется только toggle-командой; состояние приходится определять по факту
  подключения VPN-сети. В редких случаях (например, VPN ещё поднимается) возможна задержка.
- На Android 12+ фоновый запуск WDTT может блокироваться; помогает только режим «Доверенные
  сети» внутри WDTT.
- Wi-Fi имеет приоритет даже без validated/default интернета: если подключена Wi-Fi без
  интернета, приложение считает её текущей сетью, может выключить VPN по правилу доверенной
  сети, а трафик уйдёт в мобильную сеть.
- SSID — location-sensitive поле: нужны `ACCESS_FINE_LOCATION` и включённая геолокация.
  Пока открыт экран приложения, достаточно разрешения «при использовании»; фоновому сервису
  и закрытому экрану нужен `ACCESS_BACKGROUND_LOCATION` («всегда»), иначе Android возвращает
  `<unknown ssid>`. `NEARBY_WIFI_DEVICES` для SSID недостаточно. Без доступа, а также для
  скрытых сетей SSID считается неизвестным, и выбирается Tailscale.
- На API 29 тип шифрования Wi-Fi может быть недоступен: открытость сети не определяется, и
  доверие опирается на BSSID. Гарантией подлинности точки это не является.
- Фоновый доступ к местоположению требует отдельной декларации в Google Play: при публикации
  нужно обосновать, зачем приложению `ACCESS_BACKGROUND_LOCATION`.
- Приложение не может выдать другому приложению VPN-разрешение или разрешение на уведомления.
- OEM-прошивки могут убивать foreground-сервис; требуется разрешить автозапуск и снять
  ограничения батареи в настройках производителя.
- Если активен неизвестный VPN (`OTHER`), автоматика не трогает его и сообщает об ошибке.
  При известном `ownerUid` чужой пакет определяется сразу; адреса и маршруты проверяются,
  только когда владелец неизвестен, поэтому на старых версиях и части прошивок возможна
  путаница.
- Семантика паузы WDTT, доставка broadcast Tailscale и подтверждение exit node, поведение
  Doze и OEM-ограничений foreground-сервиса, IME и edge-to-edge проверяются только на
  устройстве: unit-тесты и CI этого не покрывают.
- Unit-тесты покрывают только чистую логику (`Logic.java`); instrumentation-тестов и прогона
  на эмуляторе нет.
- Старые APK в `dist/` не удаляются: `build.sh` только перечисляет их с предупреждением.
